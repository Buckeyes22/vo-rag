# Capabilities

[README](../README.md) · [Architecture](architecture.md) · [Data model](data-model.md)

Everything vo-rag does, in rough order of importance. The first three rows are the headline features. Each row names its entry point (a CLI command, HTTP route, MCP tool or process) and the page that explains it. "Opt-in" means the capability exists and is tested but is off until you enable it.

| Capability | What it does | Entry point | Page |
| --- | --- | --- | --- |
| **Crash-safe ingestion with opt-in atomic publication** | A dispatcher claims verified envelopes with `FOR UPDATE SKIP LOCKED`, heartbeats every 60 s and reclaims stale work after 15 minutes. A DAG (register, parse, chunk and embed, sterilize, register-artifact, validate, smoke gate) runs on every ingest and records validator and smoke findings as warnings (the smoke gate needs a configured LLM endpoint and is recorded as `skipped` without one). With `VORAG_INGEST_GENERATIONS=1` it runs under a 15-minute generation lease (`staging`, `validated`, `active`, `quarantined`, `failed`, `superseded`): points are queryable only once the generation is `active`, and a database constraint refuses to activate one that failed validation or the smoke gate | `python -m vo_rag.pipelines.book_rag.dispatcher`; [`dispatcher.py`](../src/vo_rag/pipelines/book_rag/dispatcher.py) | [ingestion](ingestion.md), [reliability](reliability.md) |
| **Rights-aware retrieval: raw and sterile evidence, three query modes** | Sterilization rewrites passages into facts and concepts in `vo_rag_books_sterile_v1` (opt-in: no per-run flag exists, and the shipped runner leaves it off; enable it by constructing the pipeline with `BookRagConfig(sterilize_enabled=True)`). `internal` searches raw text; `publication` and `partner` search sterile text and filter to the `cleared` and `public_domain` license classes. Public answer modes fail closed with 403 until a compliance gate is supplied, and the route calls that gate per request (deny, error or invalid gate returns 403) | `mode` on `vo-rag query`, `vo-rag answer`, `POST /api/v1/query`, `POST /api/v1/answer`; [`query_mode.py`](../src/vo_rag/core/retrieval/query_mode.py) | [rights and compliance](rights-and-compliance.md) |
| **Book-aware parsing and chunking engine** | Detects format, parses PDF, EPUB, MOBI, Office and HTML, rejects or routes each file on CPU before ingest, drops corrupt, contents, boilerplate and OCR-noise text, and builds chunks that each carry their heading path | `vo-rag preflight`; [`core/parsing`](../src/vo_rag/core/parsing), [`core/chunking`](../src/vo_rag/core/chunking) | [parsing and chunking](parsing-and-chunking.md) |
| Hybrid multi-vector retrieval | Dense, sparse and BM25 lanes fused with RRF (k = 60) and a two-pass dedup, optional reranking and visual-intent filtering (DSI-routed search exists as library code only; no query path calls it); ColBERT vectors are optional at ingest (`VORAG_BOOK_RAG_INCLUDE_COLBERT=1`) and are stored, not used for ranking | `vo-rag query`, `POST /api/v1/query`, `vo_rag_query`; [`search.py`](../src/vo_rag/core/retrieval/search.py) | [retrieval and answers](retrieval-and-answers.md) |
| Cited answer synthesis with injection defense | Retrieval, then a protected completion: untrusted wrap with a canary, JSON output, post-hoc validation. Profiles `quality`, `fast`, `kimi_benchmark` and `local`. Writes `answer_log` and `citation_assignments` rows | `vo-rag answer`, `POST /api/v1/answer`; [`answer.py`](../src/vo_rag/api/routes/answer.py) | [retrieval and answers](retrieval-and-answers.md) |
| Security controls | Fail-closed API-key or Access-JWT auth, CSRF for browser mutations, query-scope enforcement, SSRF block lists with DNS pinning and redirect re-validation, prompt-injection defenses, quarantine-by-default trust, bidi-override stripping, secret masking | API middleware; [`auth.py`](../src/vo_rag/api/auth.py), [`url_safety.py`](../src/vo_rag/web/url_safety.py) | [security](security.md) |
| Source publication revisions and copy-on-write repair | Each source has a durable revision job; reads filter by an active-revision pointer so a query pins one revision. Repair replays the normal producer from an immutable evidence file | `vo-rag corpus-repair plan`, `preflight`, `apply`, `resume`, `verify`; [`source_publication.py`](../src/vo_rag/core/ingest/source_publication.py) | [reliability](reliability.md), [operations](operations.md) |
| Self-retrieval smoke gate and eight-check validator | After ingest, when an LLM endpoint is configured (otherwise recorded as skipped), queries generated from a book's own chunks are checked for retrieving them within top-k (decision `pass`, `quarantine` or `fail`); the validator runs eight structural checks with degeneracy floors. Both record warnings; in generation mode a failing result blocks activation | Inside the ingest workflow; [`retrieval_smoke.py`](../src/vo_rag/pipelines/book_rag/retrieval_smoke.py), [`validator.py`](../src/vo_rag/pipelines/book_rag/validator.py) | [ingestion](ingestion.md), [evaluation](evaluation.md) |
| Evaluation and regression gate | Per-pipeline fixtures (queries, qrels, baseline); modes `replay_smoke` and `retrieval_gate`; fails closed when the qrels hash or corpus drifts; judge calibration; answer evaluation | `vo-rag eval-gate`, `make eval-demo`; [`run_eval_gate.py`](../scripts/run_eval_gate.py), [`run_answer_eval.py`](../scripts/run_answer_eval.py) | [evaluation](evaluation.md) |
| Interfaces: HTTP, CLI, MCP, portal | The same services behind four surfaces | `vo-rag`, `vo_rag.api.main:app`, `python -m vo_rag.mcp.server`; [`portal`](../packages/portal) | [api](api.md), [cli](cli.md), [mcp](mcp.md), [portal](portal.md) |
| Ingest surfaces | Presigned upload and verified file-drop envelopes, which the dispatcher ingests; URL, text and idea envelopes, which are stored but not yet consumed by any pipeline; and a streaming progress endpoint. `dispatch_status` is `queued` only for a verified file drop while the dispatcher heartbeat is fresh | `vo-rag ingest file`, `file-drop`, `text`, `url`, `idea`; `POST /api/v1/intake`; `vo_rag_ingest` | [ingestion](ingestion.md) |
| OCR: docling OCR and the OCR farm | Plans a backlog, splits books by page range, runs longest-first across ssh hosts or RunPod pods, and caches `ocr/<sha256>/docling.json`. The RunPod variant refuses when the estimate exceeds the remaining budget and sets pod TTL to the estimate plus 25% | `vo-rag corpus ocr-farm plan`, `run`, `runpod run`; [`ocr_farm`](../src/vo_rag/ocr_farm) | [ocr](ocr.md) |
| Visual and figure pipeline | Extracts figures, builds composite figure chunks, optionally describes them with a vision model, and serves figure bytes from disk | `GET /api/v1/figures/{src}/{filename}`; [`visual_sidecar.py`](../src/vo_rag/pipelines/book_rag/visual_sidecar.py) | [ingestion](ingestion.md) |
| Advanced layers with STOP/GO gates | Summary tree, RAPTOR, DSI and an entity graph, each persisted to its own collection by a build command (opt-in). Each has a STOP/GO decision function over A/B scores you supply; these are library code that no `vo-rag build` command runs, and DSI routing is not on the query path | `vo-rag build summary`, `raptor`, `dsi`, `graph` | [advanced layers](advanced-layers.md) |
| Corpus maintenance loops | Detect (health, duplicates, boilerplate), record (reports), fix (purge, re-ingest), verify (canary gates, rechunk preview) | `vo-rag corpus health`, `purge`, `duplicates`, `boilerplate`, `canary-report`, `rechunk-preview` | [operations](operations.md) |
| Reviewed tagging workflow | A human-in-the-loop cycle that loads draft tags, exports sheets for review and applies reviewed tags to books and chunks | `vo-rag corpus tf-books`, `vo-rag corpus tf-chunks` | [integrations](integrations.md) |
| Reliability mechanisms | Qdrant read retry with backoff, embedding-client retry and body-size guard, an on-disk embedding cache, an LLM retry policy, a budget gate with 50, 75 and 90% thresholds, a serverless health probe with eight verdicts | [`qdrant.py`](../src/vo_rag/core/storage/qdrant.py), [`client.py`](../src/vo_rag/core/embedding/client.py), [`serverless_health.py`](../src/vo_rag/core/cloud/serverless_health.py) | [reliability](reliability.md) |
| Observability | Prometheus series, a 20 s operational sampler (dispatcher heartbeat age, oldest claimable age, publication pending age), OpenTelemetry spans, structured logs and the `query_log` audit table | `GET /metrics`; [`metrics.py`](../src/vo_rag/core/observability/metrics.py) | [observability](observability.md) |
| Cloud cost governance | A monthly budget, alert thresholds and a kill switch that blocks network access and terminates tagged pods (the kill switch is a tested building block that nothing in the codebase calls automatically), with a Prometheus exporter | `python -m services.cloud_cost_exporter.app`; [`cost_tracker.py`](../src/vo_rag/core/cloud/cost_tracker.py), [`kill_switch.py`](../src/vo_rag/core/cloud/kill_switch.py) | [operations](operations.md) |
| Workers and inference services | A unified GPU worker for embedding, reranking and a vision gateway, a standalone embedding worker, RunPod vLLM contracts, and a worker registry checked against the static workload router | `vo_rag.workers.inference.server:app`; [`registry.py`](../src/vo_rag/workers/registry.py) | [architecture](architecture.md), [operations](operations.md) |
| LLM seam and providers | One client for every LLM call: typed errors, retry, structured output, prompt registry with variants, cost and trace recording; providers Anthropic, Kimi, llama.cpp and RunPod serverless | [`client.py`](../src/vo_rag/core/llm/client.py) | [architecture](architecture.md) |
| LlamaIndex integration tier | Adapters that expose the production retrieve, rerank and synthesize path to LlamaIndex, agents on those adapters, and a LlamaIndex port of the ingest DAG | [`integrations/llamaindex`](../src/vo_rag/integrations/llamaindex) | [integrations](integrations.md) |
| Video extraction pipeline | A resumable per-(video, stage) runner with pluggable transcription, a JSON export contract and a seven-check validator. Listed as planned in the roster | `vo-rag vce run`, `status`, `validate`; [`pipelines/vce`](../src/vo_rag/pipelines/vce) | [integrations](integrations.md) |
| `brain_sync` Markdown indexer | Indexes a Git repository of Markdown pages into `vo_rag_brain_v1`, one chunk per heading, reading a Git ref rather than the working tree, with deterministic IDs and a state file | `python -m vo_rag.ops.brain_sync`; [`brain_sync.py`](../src/vo_rag/ops/brain_sync.py) | [operations](operations.md) |
| Reddit archive ingestion | Renders each archived post and its comment tree as one Markdown document and ingests it through the file-drop path | [`reddit_archive.py`](../src/vo_rag/core/ingest/reddit_archive.py) | [ingestion](ingestion.md) |
| Configuration | 18 settings sections validated with unknown keys rejected, `${VAR:default}` interpolation and a `VORAG_SETTINGS_PATH` override | [`settings.py`](../src/vo_rag/core/config/settings.py), [`settings.yaml`](../config/settings.yaml) | [configuration](configuration.md) |
| Persistence layout | 47 Postgres tables, 19 Qdrant collections, object-store keys, a figure store and an embedding cache | [`qdrant.py`](../src/vo_rag/core/storage/qdrant.py), [`migrations`](../src/vo_rag/core/db/migrations) | [data model](data-model.md) |
| Privacy | PII redaction at levels `off`, `standard` and `strict`, and purge by source through deterministic IDs | `vo-rag corpus purge`; [`redaction.py`](../src/vo_rag/core/observability/redaction.py) | [security](security.md) |
